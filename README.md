# dsh-skill-manager

DeepSeek Harness 技能管理器 · v0.3.7

在对话输入栏提供「技能」入口，管理统一用户技能库、当前会话的多技能开关与技能集合。导入是复制，而不是链接下载目录；保存后删除下载源，不影响已安装的技能与资源。

## 新版使用方式

| Before | After | Why |
| --- | --- | --- |
| 选择技能后追加 slash 到草稿 | 完整列表，每项独立开关，多个技能可组合 | 保持当前会话的技能选择，不修改或发送草稿 |
| 集合与技能分区，操作和说明拥挤 | 同一分层背景列表，集合优先并显示「集合」标签和成员数，成员/详情按需展开 | 用户按一个入口浏览技能及组合，行内布局保持整齐 |
| 刷新与会话设置占用列表上方 | 搜索下方满宽「全部关闭 / 新建集合」，右下角圆形悬浮刷新 | 减少常驻设置区，保留权威状态刷新及键盘可达性 |
| 开启数量只在面板内查看 | 输入栏「技能」入口旁显示数量，0 灰色、非零绿色 | 不打开面板也能知道当前会话已启用数量，不将已启用误称为正在执行 |
| 已有技能在面板内编辑正文 | 开关旁直接提供文件、重命名和删除图标；文件按钮交给本机默认程序打开 | 移除用户报告的输入故障触发入口，不再把已有技能正文载入面板 |
| 集合「更多」只显示集合级操作 | 「更多」展开全部成员，每个成员都有完整开关与图标操作 | 不在外部重复成员，也不隐藏成员的管理入口 |
| 每次只导入一个技能目录 | 递归识别多层文件夹及 ZIP / RAR / 7z | 一个技能为独立项，多个技能为集合 |
| 英文名称既是显示名称也是路径 | 中文显示名称与稳定内部身份分离 | 重命名不破坏资源和集合引用 |
| 从空白表单创建，每题必须打字 | 十题均有默认推荐和其他预设，可选自定义（包括类型），零输入可生成后检查与编辑 | 默认路径真正可完成，又不限制有明确需求的用户 |
| 集合按名字加载，项目同名可能挡住全局副本；所有409均提示重试 | 所选稳定 ID 明确绑定库文件与资源；版本、来源、正文等错误分别提示 | 开启的是用户选择的副本，不把真正的来源错误当成重复点击能解决的冲突 |
| 集合编辑挤在技能库列表里，成员多时还要滚动 | 「新建集合 / 编辑集合」打开独立弹窗，背景隔离、内部滚动、底部固定保存 | 长成员列表不再撑高主列表，取消与保存边界明确 |
| 重命名跳转到面板内表单 | 名称原位变成输入框，右侧保存 / 取消图标，Enter 保存、Esc 取消 | 高频改名少一次跳转，不离开列表上下文 |
| 集合操作藏在展开区底部 | 集合开关旁直接显示重命名与删除图标 | 不展开集合也能快速改名或删除 |
| 同一技能在多个集合中需逐处改名 | 按稳定 ID 同步更新所有引用处名称 | 共享成员不会只改到一处 |

### 当前会话开关

- 开启一个或多个技能，后续轮次在宿主 `agent/pre-step` 阶段应用其真实指令与资源基础目录，不仅是插入草稿。
- 状态按会话保存，重开面板与插件重载后恢复；不同会话、子会话不自动继承。
- 开关不发送消息、不启动额外轮次，不改变正在运行轮次的技能快照；下一轮生效。
- 关闭只停止未来自动应用，**不删除历史对话里的技能指令**。手动调用技能以及模型按任务选择技能仍是另外的机制。
- 集合与单项开关明确绑定用户库中所选技能的实际文件和资源目录，以宿主原生技能解析器读取；项目里的同名技能不会替换它，也不会因为项目同名而阻止开启。仍核对稳定 ID、内部名称、真实路径、资源和正文，不猜测来源，不注册或改写项目技能。
- 同回合手动调用只有明确证明文件与资源来源相同才去重；仅同名不能证明相同。缺失、不可调用、来源异常或正文发生并发变化时拒绝启用并显示具体原因。
- 宿主会话、技能服务不可用或发生并发冲突时显示原因；状态以服务端确认为准。
- 入口旁数量表示当前会话**已启用**技能，不是正在执行的任务数。0 灰色，非零绿色；未确认时显示「—」。已确认的面板操作即时更新；面板关闭时在窗口聚焦、页面恢复可见及每 30 秒可见轮询刷新，不声称跨窗口实时推送。

### 编辑已有技能

已有技能不再提供面板内正文编辑器。开关旁依次显示「打开本地文件」「重命名」「删除」三个图标，悬停提示与可访问名称说明用途。文件按钮按稳定技能 ID 请求宿主打开受管目录内的 `SKILL.md`，不接受客户端提供任意路径或命令。

文件会交给**宿主所在电脑的默认关联程序**；如默认打开为只读预览，请在系统中将 `.md` 默认应用改为文本编辑器。成功提示仅表示打开请求已交接，不保证外部窗口已出现或文档已保存。编辑后保存并刷新技能库；请保留 frontmatter 的内部 `name`、文件位置和附属资源。外部编辑器负责保存和并发处理，不受旧面板 SHA-256 保存冲突保护；不要同时在多个程序覆盖同一文件。

文件打开不自动开启技能、不发送消息、不修改集合关系。当前回合冻结快照不变；后续回合按选定库文件经原生解析器读取，格式或身份不合法会明确拒绝。快速创建的结果检查和导入粘贴仍保留其必要输入，不属于已有技能正文编辑器。

未加载新版后端时文件按钮禁用并提示正常退出、重新打开应用。此改动移除了用户报告的触发入口，不声称已定位或修复 Electron 全局输入失效的底层根因。

### 集合弹窗与名称重命名

「新建集合 / 编辑集合」在独立弹窗中打开，不再挤在技能库列表里。弹窗挂在本插件自己的 Shadow DOM 内：打开期间背景兄弟节点被标记 `inert` 与 `aria-hidden`，关闭时逐节点还原原值（不覆盖其他弹窗留下的状态）；Tab / Shift+Tab 只在弹窗内循环，Esc 关闭。弹窗按 `visualViewport` 计算尺寸，成员列表在内部滚动、保存与取消固定在底部，窄屏（≤420px）和低高度视口下按钮仍然可见。**点击遮罩不会关闭弹窗**，避免误丢未保存的成员改动；只有明确取消、关闭按钮或 Esc 会关闭，保存进行中不关闭。

技能名称与集合名称都支持**原位重命名**：名称直接变成输入框，右侧是保存与取消图标。Enter 保存、Esc 取消；输入法组合（composition）期间的 Enter / Esc 不会误提交或误取消。名称原位重命名只发送 `displayName`（技能为 `PATCH /library/skills/:id`，集合为 `PATCH /collections/:id`），不会碰集合成员；集合弹窗的「保存」按设计同时提交 `displayName` 与当前草稿的 `skillIds` 成员列表（提交前请确认成员未被误改）。保存请求未返回时输入框只读、按钮禁用且不重复提交；失败保留草稿并显示原因。同一技能属于多个集合时，重命名按稳定 ID 同步更新所有出现位置。重命名期间搜索框只读、导航/收起/删除入口禁用，以免丢草稿；弹窗打开期间背景整层被 `inert` 标记，背景控件无法交互。取消或保存后焦点都回到发起重命名的图标，弹窗关闭后焦点回到打开它的按钮。两者都只在文档仍聚焦、且焦点还停在原位或宿主上时归还——用户一旦把焦点移到别处就不再抢回；若触发按钮因紧接的刷新短暂变为禁用，会按帧等待其可用（上限 800ms），避免静默丢失焦点。

### 技能集合

创建多个集合、编辑成员、中文重命名。点击集合名称或「更多」展开全部成员，各成员均有独立开关及文件、重命名、删除图标；**集合的开关旁直接提供重命名与删除图标**，展开区顶部保留「编辑集合」入口（增删成员）。一项技能可属于多个集合。已有集合归属的技能只在所属集合内显示，不在外部列表重复显示；搜索成员名称会保留所属集合，展开可访问成员。删除最后一个集合归属后技能重新出现在独立列表，空集合仍可见。集合一键开 / 关其所有成员，同时允许单独改变成员开关；部分开启显示混合状态。删除集合仅删除成员关系，不删除技能。删除技能会从所有集合移除引用。

### 导入与命名

1. 选择 Markdown、多层文件夹，或 ZIP / RAR / 7z 压缩包，也可粘贴 Markdown。
2. 预览自动识别的技能：一个作为独立技能，多个作为集合。
3. 为技能 / 集合取中文名称，可逐项调整成员名称；确认后才写入用户库。
4. 每项完整复制为用户库的独立技能目录，包含其 `SKILL.md` 和相对脚本、图片、参考文件等。集合不增加额外目录层级，兼容宿主一级扫描。

新导入同名技能不会覆盖已有目录，自动分配独立内部名称。显示重命名不改内部 `name` 或文件资源。现有用户技能无损纳入列表。

**资源归属边界**：父子目录同时存在 `SKILL.md` 时拒绝有歧义的导入；技能根外的共享脚本、资产与配置不会猜测归属，需整理成独立完整技能。根外 README / LICENSE / NOTICE / .gitignore 等仓库说明可明确警告后忽略；技能目录内部文件完整复制。压缩包支持多层文件夹，不递归解压压缩包里的另一个压缩包。

**支持限制**：拒绝加密、分卷、自解压及 ZIP64；RAR4 已本机实测，RAR5 未完成专项验证。只导入可信内容；导入或开启不会自动执行技能脚本，也不提升文件访问权限。

### 本地快速创建

选择程序开发、UI 设计、写作与内容、研究与分析或其他工作，每个问题均有已选推荐答案及其他预设，**无需键入文字即可完成全部十题**。类型、具体目标、环境、输入、流程、约束、输出、验收、示例与名称，每题也都提供「自定义答案」（类型题为「自定义类型」）。只有选择自定义才显示输入框；可返回修改，切换类型会更新预设并保留明确填写的自定义答案。最后展示结构检查和可编辑正文，用户确认后保存。

该功能**不调用 AI，不消耗模型额度**。结构检查及文本长度门槛只能帮助减少遗漏，不能保证技能内容正确或“完美”。建议先在低风险任务试用，再按结果修改。

## 主题 / UI 美化兼容

- 入口与面板使用独立 Shadow DOM，不向宿主注入全局样式。
- 透明、半透明、无效主题背景合成为不透明颜色，校正文字对比与冲突分层。
- 保留键盘焦点、Tab 约束、方向键页签、IME 友好的 Esc、外部点击关闭、窄屏布局和减少动态效果支持。
- 隔离外部通用 CSS 与 `!important`；不保证第三方 JavaScript 直接删除组件、隐藏 / 缩放整个祖先页面仍不影响插件。

## 管理范围与数据

只管理 `DSH_HOME/skills`，默认 `~/.dsh/skills`；不接管项目 `.dsh/skills`、`.agents/skills` 或其他来源。管理器的持续开关以用户库稳定 ID 绑定实际路径，使用宿主文件系统技能提供器直接解析指定文件，不依赖按名称查找的项目优先结果或目录扫描缓存。手动调用及宿主普通技能目录仍按 cwd / preset 解析。原生加载器不可用时，兼容路径只接受宿主 registry 中路径、资源基址和正文均与指定库技能完全匹配的对象；同名项目副本、缓存不一致或缺失均明确拒绝，不退回到其他来源。

隐藏元数据 `.skill-library.json` 保存显示名、稳定 ID 与集合；`.activation.json` 保存各会话开关。请备份整个用户技能库而不只是 Markdown。导入预览有十分钟有效期，绑定认证范围且只能提交一次。

## 构建与验证

React / ReactDOM 由宿主提供。压缩解码使用固定 `7zip-bin-full@26.3.1`，包含完整 7-Zip，不能用仅支持部分格式的 7za 替代。二进制约 80 MB，多平台分发许可及源码获取见 [解压依赖许可](./src/ARCHIVE-LICENSES.md)。

```powershell
npm.cmd ci --ignore-scripts
npm.cmd run verify
```

测试使用临时 `DSH_HOME`，不修改真实用户技能。客户端构建将本地问答模块内联到 bundle，不能手改产物。验证范围和生产边界见 [验证记录](./VERIFICATION.md)。

## 安装 / 更新

下载或克隆本仓库后，在仓库目录执行上面的构建命令，再安装本地目录：

```powershell
# 在仓库目录执行；使用其他 profile 时请替换 desktop
 dsh plugin --profile desktop add "$PWD"
# 卸载
 dsh plugin --profile desktop remove dsh-skill-manager
```

**后端更新后，请保存工作，正常退出并重新打开当前 DSH 桌面应用，再查看现有页面。只刷新页面或关闭/重开技能面板，不等于重载宿主模块。** 本机 desktop 已以 `link:` 安装这份源码；只读调查发现宿主默认 `hmr.root: []`，不会自动清除链接包后端的模块缓存。客户端必须先执行 `build:client` 生成产物，客户端 HMR 与后端重载是两回事。已有包的安装流程也可能返回 `restart-required`，不能将重新安装视作后端已热更新的证据。

复制安装的环境仍需先更新实际安装副本。本次不自动终止运行中的应用、不启动替代服务器、不修改真实技能库。会话扩展按本机宿主 `0.2.0-rc.2` 的真实协议实现，其他宿主版本需验证相应事件和服务。Node >=22.5；文件夹选择依赖浏览器 `webkitdirectory`。

## HTTP API

前缀 `/dsh-skill-manager/api`，先经过宿主 Host / Origin / 登录 gate。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/library` | 技能、集合、库位置与模块加载时捕获的 `runtime` 版本/能力；`apiVersion:2` |
| POST | `/import/preview` | `{files,sourceName}` / `{path}` / `{fileName,content}` / `{archive:{fileName,content}}` |
| POST | `/import/commit` | `{token,displayName,names?}`，确认后独立复制 |
| POST | `/library/create` | `{displayName,description,content}` |
| POST | `/library/skills/:id/open` | 空请求体，按受管 ID 交接本机默认程序打开技能 Markdown；`{opened:true}` 仅表示交接成功 |
| GET | `/library/skills/:id` | 兼容 API：完整 Markdown 与文件版本 `revision`；新版列表不再读取正文编辑 |
| PATCH | `/library/skills/:id` | `{displayName}` 重命名，或 `{content,expectedRevision}` 安全编辑；并发冲突返回 409 |
| DELETE | `/library/skills/:id` | 删除技能并清除集合引用 |
| POST | `/collections` | `{displayName,skillIds}` |
| PATCH / DELETE | `/collections/:id` | 编辑名称和成员 / 删除集合 |
| GET | `/activation?sessionId=…` | 当前会话的 `skillIds`、`revision`、可用性 |
| POST | `/activation` | `{sessionId,skillIds,expectedRevision}`，拒绝返回真实原因及类型化 `code`；只有状态版本冲突要求同步后重试 |

activation 的冲突代码区分 `ACTIVATION_REVISION_CONFLICT`（版本）、`ACTIVATION_SOURCE_CONFLICT`（来源）、`ACTIVATION_CONTENT_CONFLICT`（正文）、`ACTIVATION_SKILL_UNAVAILABLE`（技能不可用）及 `ACTIVATION_LOADER_UNAVAILABLE`（原生加载器不可用且无法证明兼容对象身份）。失败不会保存新的开启列表；客户端可以重新读取状态，但不会自动重发开启请求。

旧 `/skills` API 保留兼容，不是新版面板使用的接口。上传文件采用 `{path,content,encoding:'base64'}`；压缩包 `content` 为严格 base64。v0.3.7 移除插件自身的 JSON 请求 24 MiB、导入资源 / 压缩包 / 解压总量 16 MiB、待确认预览总量 64 MiB 上限；扫描、创建和后端正文编辑也不再按原 16 MiB 大小拒绝技能。仍最多 2048 文件、32 个待确认预览（10 分钟过期），保留路径、压缩比、并发和超时检查。技能库元数据 16 MiB 与 activation 状态 4 MiB 是独立控制文件保护，不是导入容量配额。当前上传 / 预览 / 解压仍在内存中处理，大文件可能导致高内存占用或运行时失败；不保证无限容量或绕过宿主 / 代理 / Node 的运行时限制。拒绝路径穿越、符号链接 / junction、ADS / 设备名、重复路径和目录冲突。新版导入独占创建全新目标目录，以 `wx` 写入资源，全部资源完成后才发布各技能 Markdown，**不再将 `.library-stage-*` 整目录 rename 为技能目录**；不会合并或覆盖已存在目标。事务标记与元数据控制插件可见性，失败先撤销新技能 Markdown 再清理自建目录；宿主可能短暂看到已完整发布、尚未提交元数据的新技能，因此不是操作系统级多目录原子事务。

旧兼容 API 编辑已有技能与元数据保存仍使用原子文件重命名（外部编辑器的保存方式不受插件控制），Windows 临时 `EPERM` / `EBUSY` 采用有界重试，不以原位截断或复制覆盖已有文件兜底。持续占用或权限不足时返回包含 `diagnostic.code/operation/source/target/runtime` 的错误并尝试回滚；若持续锁定也阻止回滚 / 清理，会明确报告残留路径或保留的备份，不声称已完全恢复。若仍失败，请关闭正在访问技能文件的编辑器 / 资源管理器窗口，核对目录权限及安全软件拦截记录后重试；不需要手动删除已有技能。

解压先完整路径 / 元数据检查，再逐文件读标准输出，不按归档路径写磁盘；限并发、超时、列表 / 错误输出及压缩比；每个资源的实际解压输出不得超过声明大小，不再设置固定解压总容量上限。原生解码器**没有 OS 级内存硬上限**，恶意归档的更强隔离仍需 Job Object / cgroup 等系统沙箱。
